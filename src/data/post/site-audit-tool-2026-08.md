外部のサイト診断サービスにURLをかけたところ、スコアが37点と出ました。

指摘を1件ずつ実際のサイトで確かめていくと、**そのうち4件が事実と違いました。** 一方で、指摘されていないところに、表示速度を大きく損なう問題が見つかりました。

「診断結果を検証する手間」のほうが大きくなってしまったので、自分で検査ツールを作ることにしました。この記事では、そのツールが何を見ているのかと、**自社サイト2つで実際にどこを直したのか**を書きます。

---

## なぜ自分で作ったのか

外部サービスの指摘を検証した結果は、次のとおりでした。

| 指摘された内容 | 実際 |
|---|---|
| AIクローラー（ChatGPT等）をブロックしている | robots.txtでは許可済み。各クローラーの名前でアクセスしても正常に応答していた |
| パンくずナビがない | 下層ページには全て設置済み。トップページだけを見て判定していた |
| FAQ形式のデータがない | 実装済み。同じくトップページしか見ていない |
| 画像のalt属性が59%しか設定されていない | 未設定分は全て装飾目的のアイコンで、`alt=""` が正しい実装 |

最後の1件は特に問題で、**指摘どおりに直すと、かえってアクセシビリティが悪くなります。** 装飾目的の画像に意味のない説明文を入れると、読み上げ環境では余計な情報が読み上げられてしまうためです。

スコアを上げること自体を目的にすると、こういう「直したほうが悪くなる」対応をしてしまいます。**指摘が事実かどうかを自分で確かめられる状態**が必要でした。

## 何を検査しているのか

サーバーやCMSへのログイン情報は不要で、URLを1つ渡すだけで動きます。8つの分野を見ています。

| 分野 | 主な検査内容 |
|---|---|
| クロール・インデックス | サイトマップに実際に到達できるか、noindexページが混ざっていないか |
| レスポンスヘッダー | セキュリティ関連のヘッダー、静的ファイルのキャッシュ設定、圧縮 |
| パフォーマンス | サーバーキャッシュが効いているか、サーバー応答速度、画像フォーマット |
| メタ情報 | タイトル・説明文の長さと重複 |
| 構造化データ | 事業者情報、パンくず、記事情報、著者情報 |
| AI検索対応 | AIクローラーの許可状況、llms.txt、FAQデータ、記事の量 |
| 内部リンク | リンク切れ、リダイレクト経由のリンク、URLの読みやすさ |
| 画像・アクセシビリティ | alt属性、言語設定 |

誤検知を避けるために、判定のしかたを3つ工夫しています。

- **AIクローラー**：robots.txtの記述だけで判断せず、実際にそのクローラーの名前でアクセスして応答が返るかまで確認します。robots.txtで許可していても、サーバー側の設定で弾かれているケースがあるためです
- **alt属性**：アイコンや背景写真などの装飾目的の画像を除外し、**情報を持つ画像だけ**を対象に判定します
- **パンくず・FAQ**：トップページだけでなく、全ページを走査して判定します

診断結果は毎回データベースに記録しているので、改善の推移を追えるようにしています。

## 自社サイトで実際に直したこと

作ったツールを、まず自社の2サイトにかけました。以下、実際に直した内容です。

### 表示速度：キャッシュが1度も効いていなかった

一番影響が大きかったのはこれでした。

サイトに導入していたチャットボットが、**全ページでセッションを開始する実装**になっていました。その結果、すべてのページで「このページをキャッシュするな」という指示がブラウザとサーバーに送られ、**サーバー側のキャッシュ機能が一度も働いていませんでした。** ページを開くたびに毎回サーバーで生成し直していたことになります。

セッションの開始をチャットの送受信時だけに限定し、会話の継続はブラウザ側で管理する方式に変更しました。サーバーの応答時間は実測で **0.09秒** になりました。

これは外部の診断サービスでは指摘されていませんでした。表示速度の数値だけを見て「画像が重いのだろう」と判断していたら、原因にはたどり着けなかったと思います。

### サイトマップが存在していなかった

`/sitemap.xml` にアクセスすると、別のURLへ転送された先が **404** になっていました。

原因は、サイトマップを生成するプラグインが有効なのに設定が空だったことです。このプラグインはCMS標準のサイトマップ機能を無効化するため、**どちらのサイトマップも存在しない状態**になっていました。設定を有効にして28ページ分を復旧し、robots.txtからも参照するようにしました。

あわせて、「検索結果に出さない」設定にしているページがサイトマップに載っていたので除外しました。矛盾した指示を送っている状態だったためです。

### URLが意味を持たない文字列になっていた

もう1つのサイトでは、カテゴリのURLがこうなっていました。

| 本来の名前 | 生成されていたURL |
|---|---|
| AI活用 | `/category/ai-huo2-yong4` |
| ホームページ制作 | `/category/hmupji` |
| 補助金 | `/category/bu3-zhu4-jin1` |

日本語をURLに変換する処理が中国語のピンインとして解釈していたためです。これらは検索結果に表示されるURLなので、英語のスラッグを個別に指定し、旧URLからは転送を設定しました。

### そのほかに直したこと

- セキュリティ関連のレスポンスヘッダーを追加（4種類が未設定でした）
- 画像104点をWebP形式に変換し、対応ブラウザにだけ配信するよう設定（ファーストビューの画像は247KB→150KB）
- タイトルタグの文字数を77字→40字に短縮（検索結果で途中が省略されていました）
- 記事ページに著者情報を追加（誰が書いた記事かのデータが出力されていませんでした）
- サイト名がタイトルに二重に付いていた8ページを修正

### 結果

| サイト | 診断前 | 診断後 |
|---|---:|---:|
| 自社サイト（Astro / Vercel） | 98点 | **100点** |
| 関連サイト（WordPress） | 97点 | **100点** |

※ 診断前の数値は、上で書いた大きな修正を終えたあとに自作ツールで測ったものです。修正前の状態は外部サービスで37点と出ていました。

## この記事で伝えたかったこと

**1つめは、診断結果は必ず一次情報で確かめること。** スコアは判断の材料であって、目的ではありません。指摘された箇所を実際に開いて、事実かどうかを見てから直す。当たり前のことですが、点数が出ると省略しがちです。
